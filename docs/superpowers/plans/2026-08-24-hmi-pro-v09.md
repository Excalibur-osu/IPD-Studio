# HMI Studio — Professional Deep Round (v0.9.x)

## Context

HMI Studio (v0.6.0 → v0.8.1) works, but the verdict driving this round is: *"it is not as a standard as well as it is not proper."* This plan measures HMI Studio against commercial packages (Ignition / FactoryTalk / WinCC) and public ISA-101 (HMI design) + ISA-18.2 (alarm management) practice, then closes the gap in shippable rounds. It is built on two full code audits and an adversarial design review. Legal rule respected: public practice articles only — no ISA standard documents ingested, no ISA artwork traced.

## What "professional" means (research, condensed)

- **ISA-101 high-performance practice**: grey theme, colour reserved for abnormal (we have this); analog indicators with limit ticks (our `bar` widget); **sparklines near key values, four display levels (L1 overview / L2 unit / L3 faceplate / L4 trend), equipment state by fill/shape** — missing.
- **PID faceplate anatomy**: PV/SP/OUT bars with limit marks, SP entry in AUTO, OUT entry in MAN, clear mode indication, units, per-tag ack — ours is a thin slider version, empty for some widgets.
- **ISA-18.2 functions we lack**: deadband/delay (no chatter), ≥3 priorities, shelving with auto-return, out-of-service, suppressed-by-design, summary with sort/filter + one-click navigation that highlights the source, operator action journal.
- **Commercial table stakes**: tag browser (never type tags), multi-pen trends with a real time axis, faceplate popups everywhere, navigation that shows where the trouble is.

## The gap list (from the code audits)

| Area | Today | Gap |
|---|---|---|
| Tag binding | Free-text `tag`/`signal`/`symbolId`; `bindTank`/`bindPipe`/`controller`/`base` have **no UI** | No picker, no validation; hand-built displays can't bind or be controllers |
| Canvas | Fixed fit-to-window 1600×1000 | No zoom/pan; Ctrl+D only (no copy/paste); pipes: no vertex add/delete, no segment drag |
| Faceplate | Fixed position, thin, **empty body for `bar`/`symbol`**; no bars/limits/units/ack; MAN→AUTO kicks (stale integrator) | Not a DCS faceplate |
| Trend | Single pen, 600 samples by index, no timestamps | No time axis, no multi-pen, no span/cursor |
| Alarms | 2 priorities, exact-limit compare | Chatters at limits; no shelving/OOS/SBD; summary has no sort/filter; navigation doesn't highlight the widget |
| Journal | Alarm events only | Operator commands not recorded |
| Screens | Theme is the only setting; `window.prompt`/`confirm` dialogs; name collisions | No reorder/duplicate/home; no L1 overview concept |
| Import | One screen per sheet, replace-only re-import | No multi-sheet dialog, no auto overview screen |
| Sim | Single-path flow (fan-out pipes carry **no** flow); instant pumps/valves | Headers/manifolds dead; no ramps/stroke/fault; no disturbance injection |
| Hygiene | `props` untyped bag; `TAG.SIGNAL` parsing ×3 copies; `patchScreen` can silently lose edits on stale screen id; sim store absent from dev hook | No schema to drive panel/picker; flaky e2e leverage |

Architecture unchanged throughout: zustand doc store + zundo, separate non-temporal `simStore` (5 Hz, seeded LCG), pure sim modules, React-SVG canvas, schema v4 with **additive optional fields only** (old `.pnid` files keep loading). HMI stays code-split.

## Phases — sized to ship one at a time (S/M/L vs past v0.8.x rounds)

### v0.9.0 — Bind (kill the free-text tag) — size M

1. **Plant tag registry** `src/hmi/tagIndex.ts`: `listPlantTags(doc)` walks all sheets' tagged nodes → `{display, letters, family, loop, hmiRole, sheetId, nodeId}`; `hmiRole` ∈ measurement / controller / motor / valve / equipment (rules mirrored from the importer); `signalsFor(role)`; one shared `parseSignalRef()` replacing the three string-surgery copies.
2. **TagPicker** combobox (type-ahead, grouped Instruments/Equipment/Valves, `expandLetters` descriptions, free text still legal) replacing raw inputs for `tag` and `signal`; new panel rows finally exposing `controller`, `base`, and **bindTank/bindPipe via "⊙ pick on canvas"** (armed click; intercepts before the selection chain and must not change the current selection).
3. **`WIDGET_SCHEMA`** in `src/hmi/model.ts`: per-type legal props with kinds — drives the panel generically and the picker context. Unknown keys **warn-only, never dropped** (future phases add props; older builds must not eat newer docs), plus a test asserting every prop key read in `src/hmi` is registered.
4. **Hygiene**: fix `patchScreen` stale-id silent-loss (resolve id like `activeHmiScreen`; the no-op path must return the identical state object so zundo records nothing); expose `useSimStore` on the dev-only `__pid` hook; status-bar toast when undo/redo inside HMI changed only the P&ID side (shared undo stack surprise).

### v0.9.1 — Author (editor parity) — size M

1. **Zoom/pan**: view `{cx,cy,k}` (k 0.5–4) threaded into `toWorld` and the `viewBox`; wheel-zoom at cursor via a **non-passive** listener (the wrap is `overflow:auto` and would scroll), Space/middle-drag pan, ⛶ fit + `Ctrl+0`; handle/vertex glyph sizes divided by k. **Edit default = fit and RUN stays fit-locked** (also keeps all existing e2e coordinate math valid).
2. **Clipboard**: module-level `Ctrl+C/X/V` (survives screen switches → cross-screen paste), copies widgets + selected pipes, paste at cursor, deep-copies props/pens.
3. **Pipe parity**: double-click segment = insert vertex, double-click vertex = delete, segment drag axis-locked (pure helpers in `editGeometry.ts`).

### v0.9.2 — Operate like a DCS — size M–L

1. **Faceplate v2** (rewrite; draggable in `.hmi-center`, position kept for the session, Esc closes):
   - **Controller**: PV/SP/OUT vertical bars, limit ticks on PV, units, AUTO/MAN chips, SP entry (steppers + clamp) in AUTO, OUT entry in MAN, alarm strip **with per-tag Ack** (uses existing `ack(id)`).
   - **Pump/motor**: state word, Start/Stop, branch flow. **Valve**: OP bar + entry or Open/Close. **Measurement/tank**: PV bar + limit ticks + unit + **60-sample sparkline** (index-based history is fine here). **Symbol**: resolves to motor/valve behaviour — no more empty bodies.
2. **Bumpless transfer** (sim): back-calculate the integrator in MAN (`I = OP − KP·e`) so MAN→AUTO doesn't kick — the thing every faceplate-literate reviewer checks.
3. **Operator command journal**: `writeTag` records CMD events (`P-101 START`, `LIC-101 SP 50→60`, mode changes); journal filter chips All/Alarms/Commands + a copy-to-clipboard button.

### v0.9.3 — See properly (trends) — size M

1. **Timestamped, signal-keyed history**: shared `historyT: number[]` (sim seconds) beside value arrays; history re-keyed by **`TAG.SIGNAL`** — PV recorded for all tags, SP/OP additionally for controllers (bounded), cap 1200. Trend consumer + tests updated; `historyT` passed only to trend/spark widgets so memoization survives.
2. **Trend v2**: multi-pen via new optional `HmiWidget.pens?: {ref, color?}[]` (additive field; `tag` stays pen 1; props bag can't hold arrays), ≤4 pens, muted palette, legend with live values; **time axis** from `historyT` with span selector 1/2/4 min **windowed by time search, not index** (speed changes make samples non-uniform); **hover cursor readout + pause-on-hover**.
3. **Sparkline option on display** (`props.spark`) — the ISA-101 "which way is it heading" element.

### v0.9.4 — Alarms to ISA-18.2 — size L (internal split line if it runs long: quality first, suppression second)

1. **Quality**: hysteresis deadband (clear at limit ∓ 1% span default, `props.deadband`) + optional on-delay (`props.alarmDelay`, tracked as pre-active candidates — the 3-phase record model doesn't change); **three priorities** low/medium/high (HH/LL→high, H/L→medium, per-widget override), shapes ■/▲/● red/orange/yellow; priority count chips in banner + status bar.
2. **Summary v2**: real table (time, priority, tag, level, trip value, state), column sort, filter chips, row click navigates **and pulses a highlight ring** on the source widget.
3. **Suppression** — designed around the audit finding that alarm records are recreated on re-violation, so state lives in a **separate suppression map** (`tag`/`tag:level` → reason + expiry) inside `simStore`, and `evalAlarms` becomes suppression-aware up front (a post-filter would spam ALARM/RTN journal events):
   - **Shelve** per alarm (5/15/30 sim-min, auto-return, SHELVE/UNSHELVE journal events), "Shelved (n)" section.
   - **Out-of-service** per tag, "Out of service (n)" section, journaled.
   - **Suppressed-by-design**: `bindPipe`-bound tags auto-suppress while their branch has no running driver (suppressed set precomputed in `tickOnce`, where branch→pump state is already at hand); badge in summary, no journal spam. Only bindPipe tags — unbound displays belong to no branch.
   - Suppressed/shelved state also shown **at the widget** (small glyph via the existing per-widget alarm-state path) — ISA-18.2 wants suppression visible at the point of display.
4. **Optional if room**: WebAudio beep on new high-priority alarm + Silence button (no dependency).

### v0.9.5 — Screens & chrome — size M

1. **Screen management**: drag-reorder tabs (new undoable `reorderScreens`), duplicate screen, ★ home screen (RUN starts there), globally unique naming. *(Per-screen background/grid was reviewed and dropped — per-page inconsistency is exactly what ISA-101 forbids; theme stays the only look control.)*
2. **Shared `<Modal>`** extracted from the backdrop+card pattern already in 3 copies (`HistoryDialog`/`DatasheetEditor`/`SymbolImportDialog`), with Esc + focus handling; replaces every HMI `window.prompt`/`confirm` (sheet picker, deletes, re-import). e2e dialog-auto-accept handlers updated in the same change (they are load-bearing today). DEXPI import's silent `hmiScreens` wipe gets a warning.
3. **Run header**: in RUN the toolbar becomes an operator header — screen title, sim clock, priority chips, **Home**.
4. **Nav alarm propagation**: nav buttons show a priority dot when their target screen has standing alarms.

### v0.9.6 — Import v2 & the L1 overview — size M

1. **Import dialog** (uses the new Modal): pick multiple sheets, per-sheet toggles.
2. **"Generate plant overview"**: auto-built L1 screen — one tile (panel + key displays + nav) per imported screen, controllers/tanks picked first, alarm dots via nav propagation; ordinary widgets, fully editable. Completes the ISA-101 L1/L2/L3/L4 ladder (L3 = faceplates, L4 = trend widgets/cursor).

### v0.9.7 — Sim depth — size L (riskiest algorithmic change, kept last and isolated in pure modules)

1. **Fan-out flow** — honest budget: a **rewrite** of `sim/network.ts` (the chain walker has no header concept): driver flow splits across parallel open branches ∝ conductance (product of valve fractions; documented as a proportional split, no pressure solve). Touches `branchFlow`, `controllerAction`, `initTags`, `pipeFlowMap` + three test suites. Fixes "manifold pipes carry no flow". SBD's branch lookup is re-pointed here (contained rework, accepted).
2. **Equipment dynamics**: pump spin-up (~2 s STARTING pulse), valve stroke time with **discrepancy alarm** (commanded vs position >10% for >5 s), FAULT state.
3. **Scenario injection** ("Events" menu in RUN): trip pump, stick valve, plug pipe, freeze transmitter — journaled, cleared by Reset. Pipe width from `lineNumber.size` lands here too, where flow finally makes widths meaningful.

## Cross-cutting rules (every phase)

- Screenshot-verify every visual change via the capture harness **before** shipping; deploy + cache-busted bundle-hash check; real-plant regression via `HMI_CAPTURE_DOC` after sim-affecting phases.
- Full gates per phase: `tsc -b`, vitest (~362 now, grows), all Playwright e2e; store-connected panel tests use the jsdom client-render pattern.
- `docs/HMI.md` updated per phase; version bump + deploy per phase, commit style `feat: v0.9.x — …`.
- Additive schema only; every new prop registered in `WIDGET_SCHEMA`; no new runtime dependencies; HMI stays code-split (`importFromPid` stays dynamic).
- Non-goals unchanged: no device connectivity, no login/security, no T/P physics models, no widget rotation. GitHub repo stays PARKED. Trend-CSV/screen-PNG export reviewed and deferred (post-arc).

## Recommended scope decision

- **Core — recommend committing now: v0.9.0 → v0.9.4** (bind, author, operate, trends, alarms). This is what "standard & proper" means operationally.
- **Extended — v0.9.5 → v0.9.7** (screens/chrome, import+overview, sim depth): confirm now or re-confirm after seeing v0.9.4 live. Order within the arc can be adjusted on request.
